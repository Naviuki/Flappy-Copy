# Changelog

## 1.0.1

**Fixed in the game**

- **Clearing a pipe pair did not add a point.** The pass sensor existed but was never created and nothing
  called the score; the spawner now creates it, samples it during a run and counts the point, and every pair
  reports exactly once.
- **The pipe run walked off the play area** after about a minute (the scroll distance grew without limits): it
  now wraps after one spacing and pairs that leave the play area are recycled to the right end of the lane. A
  wide window reveals more world, and the lane and the amount of pairs follow it.
- A run starts with the first pair in line with the bird's height (the start height is derived from the gap
  range, so tall phones do too), and every pair of a run gets a fresh gap instead of the last one it had.
- The game loop can be paused (`GameController.SetPaused`), so a tool or a window losing focus can stop the
  world without changing state.

**Project**

- 67 EditMode checks (lane wrapping, pair spacing, scoring while playing, the play area, the capped fall).
- The self-test player also passes a live pair through the scene's scoring sensor and expects the point
  (`ClearingAPipeAddsAPoint`); it is stable across repeated portrait runs and in a wide window.
- **Release script builds every installed platform** into `Builds/Release`: Windows x64 and Linux x64 archives,
  WebGL and an Android APK when their build modules are installed. `VERSION.txt` lists each archive and the
  platforms that were skipped or failed instead of hiding the ones that succeeded.
- The WebGL build settings keep the game playable from any static host (no compression format that needs
  special server headers), and the `FlappyCopy` WebGL template fills the browser window instead of the fixed
  960×600 box of the stock one; the camera, HUD, ground and pipes read the real screen size through
  `ViewMetrics`. The release ships all four builds: Windows x64, Linux x64, WebGL and the Android APK.
- GitHub Actions workflows build and publish the release archives and run the tests in CI.
- The project no longer pulls in the unused Unity module, and the old command-line harness helpers are gone.
- README/CHANGELOG/TESTS updated, `Docs/gameplay.png` recaptured.

## 1.0.0 — release

First complete version of Flappy Copy (Unity 6000.5.1f1, URP 2D, Windows x64).

**Game**

- Bird with impulse / gravity / velocity tilt; crash on pipes and ground; Menu → Playing → Game Over with
  restart from the button, a tap, Space or R.
- Pooled pipe pairs with random gap, shrinking difficulty ramp and a slowly rising scroll speed.
- +1 per pair on pass, best score in `PlayerPrefs`, "NEW RECORD!" on the result panel.
- Endless wrapping ground, clouds and town silhouette in parallax, portrait 9:16 camera and HUD.
- Four generated sound effects (flap, point, hit, ground), one `AudioSource`, a SOUND ON/OFF button that
  remembers the choice.

**Project**

- Scene, prefabs, sprites, textures and audio assets are generated by editor tooling and can be rebuilt.
- `Validate Project` checks every scene reference, prefab trigger, layer, sorting layer, the audio service, the
  input handler and the build list.
- 60 EditMode checks, a self-test player build that also plays a run, and a release pipeline that stages
  `Builds/Release` plus a zip with SHA-256 hashes.

**Fixed during release hardening**

- The bird had a trigger collider only on the visual child while `CollisionRelay` sat on the root, so
  collisions were never reported; pipes had hitbox objects without colliders at all. The bird root now owns a
  trigger `CircleCollider2D` next to its relay and both pipe hitboxes are trigger `BoxCollider2D`s, so the game
  can actually end a run on a pipe or the ground (covered by the self-test player's scripted run).
- `AudioService` lived in `SfxLibrary.cs`; Unity only persists a MonoBehaviour whose class matches its file, so
  the component in the scene was a missing script. It now has `AudioService.cs`.
- Test results were written into `Temp/harness`, which Unity deletes on exit; they now live in `Logs/harness`.
- **World was drawn four times too small.** The white sprite was an 8×8 texture at 32 pixels per unit (0.25
  world units) while every object was scaled by its size in world units; the sprite also had a centred pivot
  although the layout positions everything from the bottom-left corner. The texture is now 32×32 with a
  bottom-left pivot (`SpriteTextures`, checked by an EditMode test).
- **Pipes and ground had holes.** Pipe columns stopped short of the ground and the top of the frame, and the
  ground only started at the middle of the frame. Pipes now span the whole height behind their caps and the two
  ground strips are half a frame wide and tile the frame.
- **Gaps could not use the upper play area** and the bird started outside the gap range. The gap centre now
  covers the whole play area and the first gap starts at the bird's height.
- **The top of the frame did not end the run**: `BirdController` now reports flying out of the top as a crash.
- **HUD scale was independent of the camera**: on a wide window it was cut at the edges and far too large. The
  canvas now follows the camera (`PortraitHudScaler`, `DeviceRect`, attached by the scene builder), so the HUD
  keeps the world's scale on phones, 9:16 and wide desktop windows.
- The self-test player now writes real screenshots (`gameplay.png`, `result.png`) next to the player.
- **Sprites had no material of their own.** A renderer without a material reference fell back to a default that
  ignores its transform scale in an edit-mode render, so a 9-unit-wide ground strip painted only 4.5 units. All
  sprites now use the generated unlit material `Assets/Materials/FlappyCopySprite.mat`, and `Validate Project`
  reports a sprite that has none.
- **The scene had no light**, while the UI sprites used the lit material; the game uses unlit sprites now and
  the scene preview adds a temporary light when a scene has none, so the capture and the editor show the game.
